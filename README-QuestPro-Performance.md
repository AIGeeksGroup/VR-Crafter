# Quest Pro 性能优化与摇杆控制

## 操作

- **右摇杆**：按头部朝向的水平投影前后左右移动，默认最高 1.2 米/秒；左右推动是平移，不是转向。
- **左摇杆**：上推升高、下推降低，默认最高 0.7 米/秒；左右轴不改变高度。
- 摇杆设有 0.2 死区，斜向移动限速，卡顿帧限制单次位移。
- **Trigger**：点击 Get 3D Model，或按住拖动单个体素。
- **右 B／左 Y**：将菜单重新放到当前视线前方。

移动的是 OVRCameraRig，模型与菜单保留在场景原位置。这是自由移动视角，没有新增墙体碰撞或重力行走系统。

## 性能修改

生成的默认方块改用每组最多 128 个体素的共享网格和一个顶点颜色材质。此次完整模型的 **9,791 个独立 MeshRenderer 已替换为 77 个渲染对象**。这个数字是渲染对象数量，不是实测 FPS 或保证的 draw call 数。

每个体素仍保留独立 Transform、BoxCollider 和拖拽组件。移动体素时仅重建所在组，静止时不重建。颜色按项目色彩空间转换；材质使用简化的面向照明，并支持立体实例化。自定义 voxel prefab 和非方块形状保留原来的渲染路径。

生成按约 3 毫秒或最多 128 个体素切片；同时修正生成阶段每帧遍历全部已生成体素来重复设置尺寸的问题。控制器状态 UI 降为每秒更新 5 次；输入/性能诊断每 3 秒写一次，120 秒后停止。

## 持续增加的 warning

截图调用栈为 `OVRManager.LateUpdate → OVRHaptics.Process → Config.Load → GetControllerHapticsDesc`。SDK 每帧查询旧式震动缓冲的采样率，并反复失败，带来日志和调用栈开销。当前场景没有使用该已弃用的震动缓冲接口。

已将 Meta XR Core SDK 201.0.0 以标准 embedded package 形式保存到项目 `Packages/com.meta.xr.sdk.core`，增加默认开启的 `OVRManager.enableLegacyHaptics` 开关。当前 Windows / Editor 场景在 SDK 初始化前关闭它，使 LateUpdate 跳过旧震动处理调用。其他 OVRManager 更新保持原样；没有过滤或隐藏 warning。其他初始化调用点仍可能出现少量警告。

这是随项目保存的 SDK 补丁，不是修改 Library 缓存。包内 `PROJECT_PATCH.md` 记录了改动；升级 Meta XR Core SDK 时需复核补丁。内嵌包保留原始内容和许可证，约 208 MiB。

## 验证与范围

- 47 项输入、摇杆和批量渲染检查通过：有效姿态读取、左右摇杆、死区、水平移动和高度、单体素网格更新、相邻体素不动、旋转/缩放根节点、禁用体素和静止缓存等。
- 10 项原场景配置及变换检查通过。
- 23 项完整 Play 检查通过：HTTP 生成 9,791 个体素、77 个渲染组、逐体素拖拽、旧震动处理关闭、摇杆组件、失败重试和再生成清理。
- 无脚本或 shader 编译错误，Unity 验证进程返回码 0；已检查最终预览图。
- 隔离测试中仍出现 Unity 编辑器搜索索引异常与 Meta MRUK 退出清理提示。HTTP 404 是重试检查主动产生的结果。

这些检查在独立项目副本中进行，Play 测试关闭了该副本的 XR 启动。原项目保留 XR 启动。**本轮尚未测得实体 Quest Pro 的优化前后帧率，也未实测新版摇杆与立体渲染效果。**

## 下一次运行

先停止旧 Play，执行 **Assets → Refresh**，等待内嵌 SDK 导入和脚本编译完成，再启动 Play。Console 出现 **`[Quest Pro Input] v4 loaded (batched voxels + joystick)`** 表示新版已加载。
